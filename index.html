About SpinChoice

Why do we get stuck? SpinChoice resolves analytical gridlock by wrapping AI recommendation engines inside a psychologically rewarding, physical spin mechanic.

The Core Dilemma Solver

Most people do not lack information — they lack commitment. SpinChoice provides the commitment. It bridges the gap between complex analytical frameworks and random, zero-intelligence coin flippers.

Type any question, speak it aloud, or pick a preset. SpinChoice generates four contextually relevant options, adds a confidence metric, lets you spin to decide, and gives an AI-driven explanation coaching you on why that decision is the perfect path forward.

Development Framework

Technical Architecture

SpinChoice uses a five-tier layered MVVM model implementing strict separation of concerns.

1

Presentation Layer (SwiftUI Views)

Declarative views acting as read-only observers of ViewModel states. Contains zero business logic, enabling quick UI iterations.

2

ViewModel Layer (@MainActor ObservableObjects)

Guarantees main-thread UI updates. Coordinates asynchronous network actions via Swift Concurrency (async/await).

3

Service Layer (Singletons)

Autonomous stateful and stateless managers (e.g. AIService, PremiumManager, SpeechService) wrapping hardware and cloud systems.

4

Data Layer (Pure Value Types)

Decoupled structures (e.g. Decision, DecisionOption, AppSettings) implementing Swift's Codable protocol.

Navigation & State

The global state uses AppState (injected via .environmentObject) as the core session state machine.

View navigation stacks are routed through NavigationCoordinator using per-tab destination stacks, resolving SPM dependency routing.

SDK Initialization Sequence:

  1. AppCheckService: Assures app attestation keys.
  2. FirebaseApp: Configures core database pipelines.
  3. PremiumManager: Configures RevenueCat bindings.
  4. AnalyticsService: Registers AppMetrica events.
  5. RemoteConfigService: Resolves remote flags.

Project Configurations

Environment Variables & xcconfig

SpinChoice uses the Secrets.xcconfig file to safely compile keys, keeping secrets out of code and binary commits.

Copy Secrets.xcconfig.template to Secrets.xcconfig in the Core/Config directory before building.

// Secrets.xcconfig - Git-ignored configuration template

// Shared Cloudflare Worker authorization key - must match Worker environment variables
APP_SECRET = your-custom-shared-secret-auth-key

// AppMetrica metrics project API key (Format: UUID)
APPMETRICA_API_KEY = xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

// Development direct OpenAI key (Only evaluated if Worker URL is not resolved)
OPENAI_API_KEY =

Security Precaution:

NEVER add a production OpenAI key to OPENAI_API_KEY. Production keys must be stored in encrypted Cloudflare dashboard variables only.

Resource Hygiene

Performance Optimization

How SpinChoice ensures fluid 60fps renders and battery optimization on consumer iOS hardware.

SwiftUI Canvas Rendering

The Spin Wheel employs SwiftUI's GPU-driven Canvas API rather than individual shape layers. This lets the device render complex wheel dynamics in a single draw pass, bypassing view tree diffing and keeping frame rates locked at 60fps.

Pre-Warmed Tac Haptics

Tactile haptic generators (UIImpactFeedbackGenerator) are initialized and warmed at application startup. This avoids the standard 50ms engine spin-up latency on the user's first interaction.

Swift Tasks & Cancellation

Heavy tasks like text transcription, network requests, and database commits run off the main thread. Spin mechanics cancel instantly (spinTask?.cancel()) if the user navigates away, preventing memory leaks and CPU waste.

Battery Conservation

Network monitors (NWPathMonitor) run on the background .utility queue. This lets iOS defer connectivity checks during system Low Power Mode, conserving battery.

Privacy & attestation

Application Security

How user inputs, secrets, and database transactions are protected within SpinChoice.

Privacy by Design

  • Encrypted API Proxy: Client binaries carry no OpenAI API keys. The Worker acts as the sole key custodian.
  • Firebase App Check: Protects database endpoints by utilizing Apple DeviceCheck and cryptographic App Attest frameworks, rejecting spoofed simulation hits.
  • On-Device Speech Engine: Waveform translations run locally using the Speech framework. No user audio is recorded or uploaded.
  • Namespaced Local Cache: User files and directories are namespaced by Apple IDs (decideai_decisions_<userID>), securing cached data.
